# Hot-loader ArgentumLoader

Цель: поставил мод из каталога — он работает сразу, без перезапуска. В JVM это возможно не для всех модов, поэтому
hot-loader сам решает, что безопасно, и честно объясняет остальное.

## Этап 1 (сделано)

`net.fabricmc.loader.impl.hotload.HotLoader.load(List<Path>)` вызывается каталогом сразу после установки.

Что делает для каждого мода:

1. читает метаданные (вместе с jar-in-jar) — `HotModDiscovery`;
2. `HotLoadAnalyzer` ищет причины, по которым мод нельзя подключить к идущей игре:
   * его миксины правят классы, которые уже загружены (Mixin применяется только при загрузке класса);
   * access widener, свой языковой адаптер, `preLaunch`;
   * вызовы `Registry.register` — реестры уже закрыты, блоки/предметы не добавить;
3. проверяет зависимости (`depends`/`breaks`) по загруженным модам и по самой пачке установки; порядок — зависимости раньше;
4. `FabricLoaderImpl.hotAddMods` — jar в classpath Knot, регистрация мода, entrypoint'ы;
5. `FabricMixinBootstrap.addLate` — подключает миксин-конфиги и сбрасывает `transformedCount` в процессоре Mixin,
   иначе Mixin игнорирует конфиги, добавленные после первой трансформации;
6. запускает `main` и `client` инициализаторы только новых модов;
7. если у загруженных модов есть `assets/` или `data/` — каталог вызывает перезагрузку ресурсов игры.

Итог — `HotLoadReport`: по каждому моду `LOADED` / `NEEDS_RESTART` (с причиной по-русски) / `FAILED`.
В списке «Установленные» у каждого мода бейдж «Активен» или «После перезапуска».

Удаление: загруженный jar Windows не отдаёт, поэтому `PendingRemovals` записывает файл в
`mods/.argentum-pending-delete`, а лоадер удаляет его на следующем старте до поиска модов.

Проверено на реальных модах: AppleSkin, Zoomify, Mod Menu, Mouse Tweaks, BetterF3, Cloth Config корректно определяются как
«после перезапуска» (они патчат `MinecraftClient`, `InGameHud` и т.п., которые к главному меню уже загружены), а пробный
мод с миксином на ещё не загруженный `ClientPlayerInteractionManager` загружается, миксин применяется, инициализатор
отрабатывает.

## Бесшовное применение (handoff)

То, что нельзя подключить на лету, применяется без видимого перезапуска (`argentum-client`, пакет `handoff`):

1. После установки/удаления мода каталог просит `Handoff.requestPrepare()`. Через 1,5 с (склеивает серии изменений)
   в фоне запускается вторая копия игры: та же JVM с теми же аргументами, главный класс `KnotClient` напрямую
   (Prism запускает через `EntryPoint`, который читает параметры из stdin, — это повторить нельзя, поэтому аргументы
   берём из `FabricLoader.getLaunchArguments`).
2. Копия создаёт окно скрытым и оконным (`WindowMixin`), молчит (`SoundManagerMixin`), доходит до главного меню и
   пишет `ready`. Всё это время в каталоге — «Подготовка клиента N с».
3. Кнопка «Применить моды»: основная игра передаёт геометрию окна файлом `go`, копия встаёт на то же место и
   показывается (`shown`), основная прячет своё окно и закрывается. Новая копия открывает каталог на «Установленных».
4. Копия умерла/зависла — остаётся текущая игра, кнопка предлагает повторить. Закрыли игру, не применив, — копия
   убивается; основная закрылась без `go` — скрытая копия закрывается сама.
5. Мод, помеченный на удаление, не загружается в копии, даже пока старая игра держит файл (`PendingRemovals`).

Замеры (оконный режим, 5 модов): подготовка копии ≈ 20 с, подмена окна — между двумя соседними снимками, окно на том же месте.

Для проверки без ввода: файл `.argentum-handoff-test` в папке игры.

## Ограничения (принципиальные)

* Нельзя «довнести» миксин в уже загруженный класс: JVM-retransform не разрешает добавлять методы и поля.
* Нельзя выгрузить загруженный мод: удаление и обновление вступают в силу после перезапуска.
* События `ClientLifecycleEvents.CLIENT_STARTED` и подобные для подключённого на лету мода не придут.

## Дальше

* Access widener для классов, которые ещё не загружены.
* Загрузка мода при входе в мир/выходе (классы игрового процесса не загружены на главном экране — расширяет охват).

* Отдельный отчёт `HotLoadReport` в файл для разработчиков модов.

пишет итог в `.argentum/hotload-report.txt`.
